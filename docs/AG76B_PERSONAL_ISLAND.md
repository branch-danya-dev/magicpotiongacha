## Implemented scope

- `IslandSession` admits only the explicitly configured owner, before loading a
  profile. A Player object and generation token fence concurrent/stale callbacks.
  Admission never selects the first person to arrive. Wrong owners are rejected
  without profile load; same-owner concurrent sessions receive retry instead of takeover.
- `PersonalIslandWorld` creates actual server-owned `Island_primary` only after
  the original offline catch-up/save succeeds. No neighbouring plots, Bazaar,
  signs, purchase pads or old hidden colliders are generated by this adapter.
  Safe spawn, release/reconnect cleanup and boundary recovery use owner identity.
- The 85×83 core retains all 13 logical stations, original offsets and hauling
  waypoints, plus existing service anchors. Built equipment uses existing prop
  plans. Station state, recipes, cargo, rewards, timers and tutorial remain in the
  unchanged server domain. The original Spellbook and Green Slime template/Idles
  remain unchanged. There are no preview-only extra pets.
- Bounded perimeter foliage reuses approved M7 templates. A quiet flat path,
  visible stone rim, foundation and four existing-style lantern anchors replace
  global terrain. `EnvironmentView` remains the sole atmosphere/light owner.
  Existing quality and motion settings remain in control; no asset upload or new lights controller.
- Inventory → Market exposes only existing `buySeed`, `shopFamiliar` and
  `buyEventGold`. Their original server prices, limits and durable handlers stay
  authoritative. The A ADR's proposed `exchangeEssence` operation was an audit
  error: Factory already rejects it. B corrects the ADR and preserves that rejection.
- AG75 client `SimplifiedScene` hiding is disabled for the new actual world.

TradeCoordinator, receipt journals and ServerSettings are unchanged. No new
RemoteEvent, currency conversion, purchase prompt, pricing or saved island fields.

unchanged Spellbook presentation acknowledgement/effects. They never choose an
owner or allocate an island. Main's Book target additionally checks `IslandId` and
actual owner. Worker/context presenters already discover anchors via OwnerUserId.

## Reproduce and open the correct artifact

From this checkout, with Node 22 and the pinned tools:

```text
npm run tools
npm test
node scripts/build-ag76-preview.mjs --owner-user-id=<actual Studio Player UserId>
```

Positive user IDs produce a separate file:
`build/PotionTycoon-AG76B-PersonalIsland-QA-Owner<ID>.rbxlx`.
Open it in Studio and use ordinary **F5**. No Command Bar step is needed.
The owner is an explicit build fixture, not a runtime client-provided credential.

`npm test` instead builds `build/PotionTycoon-AG76B-PersonalIsland-QA.rbxlx`
with owner **-1**, intended for Studio's first local multi-client test player.
It must reject a different ordinary-F5 account. Tests never overwrite a positive
owner artifact. Do not guess an account ID or disable admission to avoid rejection.
For a different account, rebuild with its actual test Player.UserId.

Initial ordinary F5 was denied because the -1 fixture was opened with the owner's
positive account ID. The owner-supplied error identified that mismatch. An explicit
owner artifact fixed startup; the owner check itself was not weakened.
