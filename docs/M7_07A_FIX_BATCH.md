# M7.1 / 07A — единый пакет исправления ошибок ДО общей проверки в Studio

**Последнее решение владельца: 06.11.2026.** Вместо преждевременного цикла «одна техническая правка → открыть Studio → владелец тестирует → ещё одна правка» сначала устранить **все известные дефекты** в одном согласованном пакете 07A, затем предоставить **одну итоговую сборку ordinary full-game Play** для комплексного приёмочного прохода. Astra вправе выполнять необходимые локальные диагностические/узкие технические проверки по ходу работы; от владельца не требуется тестировать каждый промежуточный коммит. Code/CI остаются обязательными на каждом значимом коммите. Если нужную часть невозможно доказать без нативного рендера, честно указать BLOCKED, но не объявлять дефект исправленным на основании исходного кода.

**База:** [PR #17](https://github.com/branch-danya-dev/magicpotiongacha/pull/17), кандидат 07A [9d1dbe9](https://github.com/branch-danya-dev/magicpotiongacha/commit/9d1dbe997b96194e099091ca8c90944b8513b005), [M7_TASK07A.md](M7_TASK07A.md), [первичное полное ТЗ](M7_POST07_ART_FINALIZATION.md), [Issue #21](https://github.com/branch-danya-dev/magicpotiongacha/issues/21). ## B. Как Astra работает без промежуточных проверок владельца

1. **Сверить текущий HEAD PR #17** перед правкой и составить cause/fix map для A1–A8 с конкретными модулями. Первоочередной незакрытый исходный дефект — **A1 skybox seam**; текущие A2–A6 уже имеют кандидатов реализации, которым может потребоваться доработка.
2. Изменить совместимый код/генератор/ассеты для **всех** A1–A8 одним ограниченным пакетом. Сохранять проверенные source/hash receipts, не ломать исторический immutable evidence. Не добавлять новый diagnostic camera helper и не создавать обязанность снимать screenshots/video.
3. На каждом значимом изменении запускать подходящие unit/static regressions; на завершённом HEAD — **полный npm run tools + npm test, ordinary Rojo/Play build**, source/asset hash checks и CI **Windows + Ubuntu**. Не выдавать автоматические тесты за реальную визуальную проверку.
4. По возможности выполнить локальную **узконаправленную диагностику** там, где без рендера нельзя определить причину (прежде всего skybox seams), но **не запрашивать пользователя открывать отдельную промежуточную сборку после каждого фикса**. Если native Studio недоступна из-за UI/timeout, фиксировать именно этот blocker.
5. Сдать **одну общую финальную 07A-кандидатную сборку**, её commit SHA, список A1–A8 с пометками IMPLEMENTED / NOT VERIFIED / BLOCKED и короткую инструкцию единого тестирования. Все unresolved runtime пункты обозначать честно; не заявлять «07A closed», пока владелец не проверил результат.

## C. Единый контрольный прогон владельца ПОСЛЕ исправлений

**Один ordinary full-game Play (F5) с реальными UI, камерой и включённым art**, не отдельная тестовая сцена; проверка всех известных дефектов сразу:

- [ ] Полный поворот 360°, наклон вверх/вниз, день/рассвет/закат/ночь/дождь: **нет линий швов неба** ни над землёй, ни на горизонте/полюсах.
- [ ] Подойти вплотную к холмам и оградам, вращать/зумить камеру, бег/прыжок, попытки перейти наружу: **нет camera clipping, застревания, выхода через рельеф и падения с острова**.
- [ ] На 2–3 фонарях несколько раз резко развернуться 180°/360° днём/ночью: **корпус фонаря стабилен, освещение не мигает при поддерживаемом quality**.
- [ ] Повторно нажать time set, переключить day→night, sunset→dawn и weather в середине перехода: **никаких вспышек, скачков, зависания или разворота времени назад**.
- [ ] Проходы, заборы, spawn, Factory entry, строительство/улучшение, этапы фермы/базар продолжают работать.
- [ ] Full + Reduced, затем Manual graphics 5/Automatic, Minimal/ReduceMotion; красота/удобство не должны зависеть только от максимального режима.
- [ ] Точный проверенный SHA и результаты зафиксированы текстом. **Это не снимает отдельный финальный художественный Gate A 07D после 07B+07C.**

Если любой существенный баг останется, Astra адресно исправляет невыполненные A-пункты; не пересоздаёт весь ландшафт, не переходит к 07B за счёт отказа от 07A.
